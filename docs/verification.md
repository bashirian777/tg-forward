# 验证记录

自动验证使用临时数据库、独立运行目录和模拟 Telegram 客户端，不连接 Telegram 或修改生产任务。浏览器回归使用真实 Chromium，包含模拟 API 的交互 / 布局测试，以及连接真实 Flask / RuntimeBridge / SQLite 的离线契约测试。

## 来源话题标题验证

任务开关 `include_topic_name` 默认关闭，仅允许隐藏来源时启用。来源话题当前名称作为普通文字插在自定义前缀和原说明之间，不添加括号；普通频道 / 群组不插入，General 读取默认话题名称。名称缓存 5 分钟，失败短期缓存并沿用原说明；说明超长时省略新增话题名。可靠发送保存已确定的带话题说明，重试时名称变化不会改变请求文字。

`make check` 通过 255 项 pytest、前端类型、Shell 语法及差异检查；前端构建和测试文件类型检查通过，30 项模拟 API 与 3 项真实离线 API 浏览器测试通过。覆盖前缀 / 话题名 / 原标题的顺序、无括号、空前缀或空原文、字面 Markdown 名称与实体偏移、相册单份说明、去重和过滤、复制 / 下载发送一致、General 与普通回复识别、缓存失效与改名、查询失败 / FloodWait / 取消、长度降级、可靠重试复用说明、旧配置默认关闭、非法布尔及显示来源组合拒绝、CLI / Bot 创建、前端关闭隐藏来源时清空并禁用开关、规则计数、三方合并与真实 API 保存往返。五种宽度检查无溢出。

## 任务排序验证

任务表保存整数 `sort_order`，metadata 保存 `manual / recent` 模式，排序不增加任务配置版本。旧数据库按原任务 ID 顺序迁移，新任务追加，上移 / 下移在事务里交换相邻位置；最近转发按实际时间稳定降序，无记录放最后，切回手动恢复原位置。

`make check` 通过 219 项 pytest、前端类型与 Shell 语法检查；前端构建、测试文件类型检查及差异检查通过。29 项模拟 API 与 3 项真实离线 API 浏览器测试通过，覆盖保存禁用、运行中移动、筛选 / 搜索禁用、失败恢复、刷新保留、轮询更新与跨页面同步；五种宽度无横向溢出。SQLite trigger 注入第二次位置写入失败，确认交换全部回滚且内存顺序保留。重新打开数据库验证手动位置和模式保留，已有断点、计数、去重与配置版本不受排序影响。

## 已验证的故障行为

- 下载中断后补缺失块；已记录块逐块校验 SHA-256，损坏块重新下载。
- 文件预分配大小不能代替分块完整性；成功文件仍检查块和总大小。
- 文件引用过期刷新同一源媒体；源文件删除或替换时需要人工处理。
- 上传中断保留文件 ID 和完成分块，继续上传缺失部分；完整文件重新进入下载不改变上传续传身份。
- 取消等待所有 worker 退出，避免清理后仍写文件。
- 请求响应丢失后复用持久化 `random_id`；本地发送回执避免再次发送。
- 已上传媒体引用保存在任务目录，最终发送失败可复用，引用过期后重新传输。
- 相册边界补齐，穿插消息不被断点跳过；明确跳过只处理当前媒体组。
- 失败与取消保留有归属文件，清理排除活动传输和无归属文件。

## 部署后的真实对比

停止项目服务并释放用户会话后，对同一来源的代表性文档 / 视频运行：

```bash
.venv/bin/python -m scripts.benchmark_live --task-id YOUR_TASK --message-id SOURCE_MESSAGE_ID --output /path/to/new-report.json
```

脚本与服务共用会话锁，从 `.env` 读取 API 凭据及 session，从 SQLite 读取来源任务并核对手机号。依次比较 Telethon 标准传输及 1 / 4 / 8 worker，默认最大文件 256 MiB，单次超时 180 秒。下载与标准下载的 SHA-256 比较；上传只保存 Telegram 临时分块，不发送目标消息。任一失败立即停止。

结果包含耗时、速度、CPU、RSS 和失败类型，重复至少三轮并观察磁盘、FloodWait 和网络。该脚本不测试最终相册发送、封面和目标权限，需在选定任务上另行验收。真实测试尚未执行，worker 默认值没有依据真实网络调优。

Telegram `random_id` 不保证无限期跨重试 exactly-once。媒体变更、引用失效、人工调整断点及服务端去重记录失效仍需检查。
